# Docker clean-environment install tests (2026-10-06)

Harness: `npm run test:docker` (`scripts/docker-install-tests.sh`, `test/docker/`). How to run it is in CONTRIBUTING.md under "Clean-environment install tests (Docker)". The harness runs on a Linux host with Docker 29. Every container starts from a stock image with a fresh `$HOME` and runs as an unprivileged user. The packed tarball is served from a throwaway local Verdaccio registry, so the exact client command `npx -y alza-mcp` installs the build under test. All other packages are proxied from npmjs. `ALZA_TOKEN_FILE=none` is set everywhere. Nobody signed in to any account (Alza, VS Code/GitHub, Cursor), and nothing was submitted to any external site.

`chore/distribution` taken on its own (base `4d84b02`, before 0.3.1) packs a 0.3.0 tarball whose `files` list does not include `scripts/postinstall.cjs`. Run that way, `npx -y alza-mcp` exits 1 during install with no message. Main already fixed that `files` list in #30, so the problem goes away once #37 is merged on top of main. It is listed here because the harness caught it.

## Not covered

- Claude Desktop itself: there is no Linux build. The bundle is checked the way the host app would check it (validate, unpack, resolve `mcp_config`, launch), not inside the app.
- VS Code and Cursor actually *starting* the server from their own MCP UI. That needs a signed-in chat or agent in both apps. Instead, the installed entry is launched verbatim in the same container.
- The `mcp-publisher` registry publish step in `publish.yml` (#19). It needs GitHub OIDC on a tag, and nothing may be published from a test.
- Hosted HTTP deployments (datacenter egress). Every run here uses one residential IP.

No personal data appears in these files. No login was used, and the live call was a single anonymous catalog search.
