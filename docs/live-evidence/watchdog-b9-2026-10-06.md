# Native watchdog (B9, B9a, B9b): live route discovery and create/delete run (2026-10-06)

Issue #17. Raw, redacted captures are in `watchdog-b9-2026-10-06.json`. The user id,
account email, and one-time tokens are replaced with placeholders. Watchdog UUIDs are
replaced too, although both watchdogs were deleted during the run.

**Session**: authenticated owner session. The token was refreshed through the
refresh-token grant over the Chrome-fingerprint sidecar, and the rotated refresh token
was persisted.
**Product**: `12999617` (CEN178a, pencils, 19 Kč).
**Result**: create and delete are `live-verified`. The run left no orphan watchdog: the
list was empty before the run and empty again after it.

## How the routes were found

No APK decompile was available on this host, so the routes come from the server's own
hypermedia and from the www.alza.cz web bundle. Only read-only probes were used until
the delete route was known.

1. `GET webapi.alza.cz/api/users/{id}/mainNavigation?country=CZ` (user navigation) →
   `watchDogs` → `GET /api/users/{id}/v1/watchDogs?country=CZ` →
   `{self, commodities, searchForm}`.
2. `GET /api/users/{id}/v1/watchDogs/commodities?country=CZ` returned the list (paged
   `{emptyInfo, paging, value[]}`). It was empty before the test.
3. The web bundle `cdn.alza.cz/dist/b/default.*.js` opens
   `/api/v1/users/{id}/products/{commodityId}/watchdogDialog?country=CZ`
   (`productAvailabilityWatchdogDialog`). The React chunk handles
   `removeProductAvailabilityWatchdog` through the dialog's `deleteAction` and shows
   "Watchdog_Delete_Error_NotFound" on a 404.
4. `GET …/watchdogDialog` for the test product returned the create form:
   - `POST https://webapi.alza.cz/api/watchdog/v1?country=CZ&commodityClientId={id}`
   - fields `commodityId`, `email` (pre-filled with the login address), `isTrackingStock`,
     and `price` (`max` = current price)
   - `deleteAction: null`
5. Negative probes: `GET www/api/watchdog/v1` returned 404 "No HTTP resource". The
   whitelisted `mutate_list` `set_watchdog` targets the www host, which has no route for
   this family; the dialog form points at `webapi.alza.cz`.

## Raw create, then delete (seconds apart)

| Step | Request | Result |
|---|---|---|
| create | `POST webapi/api/watchdog/v1?country=CZ&commodityClientId={id}` `{commodityId, email, isTrackingStock: true, price: 15}` | 200 `{watchdogId, commodityId, isTrackingStock, price: 15, created, actions: {delete: DELETE …/watchdog/v1/{watchdogId}, update: PATCH …}}`. The response echoes the email. |
| dialog re-read | `GET …/watchdogDialog` | `deleteAction` = `removeProductAvailabilityWatchdog`, `DELETE …/watchdog/v1/{watchdogId}?country=CZ&commodityClientId={id}`; the form method changed to `PATCH` |
| list | `GET …/watchDogs/commodities` | 1 item with `updateForm` (PATCH, `isTrackingStock`, `price`) and `deleteAction` (`watchDogDeleteForm`, `www/api/anonymous/v1/watchDogs/{watchdogId}/deleteForm`) |
| delete | `DELETE webapi/api/watchdog/v1/{watchdogId}?country=CZ&commodityClientId={id}` | 2xx with an empty body |
| verify | dialog + list | `deleteAction: null`, form back to `POST`; list empty ("Momentálně pro vás nehlídáme žádné produkty") |

## The typed MCP tools, run end to end

The run went through the real server (`buildServer` with an in-memory MCP client):
`set_toolset(watchdogs)` → `watchdog_list` (0) → `prepare_mutation(watchdog_set)` →
`watchdog_set({commodity_id: 12999617, max_price: 15, track_stock: true})` (created) →
`watchdog_list` (1 entry: `max_price` 15, `is_tracking_stock` true) →
`prepare_mutation(watchdog_delete)` → `watchdog_delete({commodity_id: 12999617})`
(deleted, resolved through the dialog's `deleteAction`) → `watchdog_list` (0).
No tool output contained the account email.

## Not exercised

- `PATCH` update (`updateForm`). `watchdog_set` refuses a product that already has a
  watchdog; the supported flow is delete, then set.
- `watchdog_delete` by `watchdog_id` uses the same DELETE route as the
  `commodity_id` path, which was run live. Only unit tests cover the `watchdog_id`
  variant.
- `watchDogs/search/results` (searching inside your own watchdogs).
- The anonymous `www/api/anonymous/v1/watchDogs/{id}/deleteForm`. It was not needed,
  because the authenticated dialog delete works.
